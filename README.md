# Life Hub

Барлық қосымшаларды басқаратын орталық: сен ассистентке жазасың, ол тапсырманы керекті қосымшаға өзі жібереді.

## Қалай құрылған

```
index.html (сенің браузерің / телефоның)
   │  кіру, чат, қосымшалар тізімі
   ▼
Supabase: my-life-system
   ├─ Edge Function «assistant»  ← OpenRouter кілті осында, құпия сақталады
   │     модельге сұрақ → модель құрал шақырады → функция дерекқорға жазады
   └─ items кестесі              ← барлық қосымшаның жазбалары (app = lang, money, ...)
         әр жазба тек иесіне көрінеді (RLS)
```

- Supabase жобасы: `my-life-system` (`lcmnkcpkbkrktediyvpo`, Frankfurt)
- Қосымшалар: Тіл, Кітап, Қаржы, Жоспар, Денсаулық, Ойлар
- Hub-тың иесі — жобада бірінші тіркелген аккаунт. Басқа ешкім деректерді көре алмайды және ассистентті шақыра алмайды.

## Іске қосу (бір рет)

1. **OpenRouter кілті.** openrouter.ai → Keys → жаңа кілт жаса.
2. **Кілтті Supabase-ке қос.** Supabase Dashboard → `my-life-system` → Edge Functions → Secrets → `OPENROUTER_API_KEY` атымен сақта. Қайта жариялау керек емес.
3. **Hub-ты аш.** https://bberikulu-itbil.github.io/life-hub/
4. **Тіркел.** «Аккаунт жоқ па? Тіркелу» → email мен құпиясөз → поштаңа келген растау сілтемесін бас. Сілтемеден кейін ашылмайтын бет шықса, қорықпа: аккаунт расталды, Hub-қа қайтып кір.
5. Тіркелгеннен кейін (қаласаң) Supabase → Authentication → Sign In / Providers бөлімінде жаңа тіркелуді өшір.

## Модельдер мен лимит

- Баптаулар бетінде өз модельдеріңді ретімен жазасың. Біреуі жауап бермесе, Hub келесісіне ауысады. Тізімнің соңына OpenRouter-дің құрал шақыра алатын тегін модельдері өзі қосылады.
- OpenRouter-дің тегін модельдері: тәулігіне 50 сұраныс; аккаунтқа кемінде 10 кредит салынған болса — тәулігіне 1000 сұраныс, минутына 20. Баптаулар → «Бүгінгі лимит» қанша қалғанын көрсетеді.
- Бір хабарлама ішінде ассистент бірнеше рет модельге жүгінуі мүмкін (құрал шақырып, нәтижесін оқу үшін), сондықтан бір хабар 2–3 сұраныс жеуі мүмкін.

## Broadcast

https://bberikulu-itbil.github.io/life-hub/broadcast/ — Life Hub MiniApp-ы: топтарға жеке хабар, WhatsApp немесе Telegram арқылы. Топ екі түрлі: **сынып** (хабар оқушының ата-анасына барады) және **адамдар тізімі** (әріптестер, үйірме — әркім өзі алады; тегтері {Алушы}, {Аты}, {Аты-жөні}).
1. **Мәтін:** тегтерді басып жазасың ({Алушы}, {Оқушы аты}, {Оқушы аты:ның} → «Рамазанның»). Бағалар кестесін қойсаң, әр баған тегке айналады. ЖИ жоба жаза алады: оған тек ақпарат пен баған атаулары барады.
2. **Кімге:** анасына (жоқ болса, әкесіне) / әкесіне / екеуіне / негізгі жауаптысына / жақын тұратын жауаптысына / барлығына. Жүгіну: аты мен әкесінің аты, аты + апай/ағай, тек аты, толық аты-жөні.
3. **Тексеру:** әр адамға баратын дайын хат; кез келгенін алып тастауға немесе қолмен өңдеуге болады («Үлгідегідей қайтару» — бастапқы мәтінге қайтарады). Кестедегі аттар тізіммен әріп ретіне, қазақ әріптеріне қарамай салыстырылады; тегі сәл басқа жазылса, ұқсас ат ретінде қосылып, 1-қадамда көрсетіледі.
4. **Жіберу:** арнаны 2-қадамда таңдайсың. WhatsApp: `wa.me/<нөмір>?text=`. Telegram: `t.me/<username>?text=`, username жоқ болса `t.me/+<нөмір>?text=` (нөмір арқылы тек ол адам нөмірін жасырмаса не сенің контактіңде болса ашылады). Әр хат бір басумен ашылады, соңында есеп.
- **Топтар:** әр сынып не тізім — бір топ (бұрынғы байланыстар «7B» тобында). Топ — кесте: оқушы, анасы, әкесі, туыстары және өзің қосатын бағандар («+ Баған»). Өз бағандарың хатта тег болады ({Бөлме} → «410»). Excel-ден қойғанда 5-бағаннан кейінгілері топтың бағандарына айналады. Топты қайта атауға және екі басумен жоюға болады.
- Байланыстар `items` кестесінде (`app = 'parent'`, `data.class` бойынша; `data.telegram` — username, тізімде `role = 'өзі'`), топ бағандары `app = 'group'` (`data.kind`: `class` / `people`, `data.columns`, `data.values`), хабарлар `app = 'broadcast'`; тек иесі көреді.

## FinSaulyq

https://bberikulu-itbil.github.io/life-hub/finsaulyq/ — қаржы мен циклдік қор: тауар қашан таусылатынын алдын ала есептейді.
- **Басты бет:** қолжетімді қалдық (көзбен жасыруға болады), мақсаттардағы сома, циклдер, шығын диаграммасы, жазбалар (өзгертуге және өшіруге болады).
- **Жоспар:** SMART мақсаттар (100% болғанда алтын түс), келесі сатып алулар, алдағы 3 айдың болжамы.
- **Қор:** циклдер, өнімдер қоры, брендтерді ₸/күн бойынша салыстыру.
- **Мәзір:** Журнал (баланс, соңғы жазбалар) · Summary (шығын бөлінісі, шоттар, болжам) · «+» · Циклдер (циклдер, мақсаттар, қор, брендтерді салыстыру) · Профиль (шоттар мен аударым, баптаулар, бұлт, көшірме). **Профильде:** санаттар мен ішкі санаттар (`fs_category`; транзакцияда `sub`, «+» 3-қадамында таңдалады, Summary-де санат астында), кіріс көздері (`fs_income`; «Түсті» батырмасы кіріс транзакциясын жасайды, Summary-де айлық орындалу %), жинақтар (= мақсаттар, Summary-де прогрессімен). **Дизайн құрылымы** (Gem Wallet үлгісінде): Summary — санаттар мен шоттардың карточка торы; Профиль — топталған мәзір (Санаттар, Шоттар, Кіріс көздері, Жинақтар, Параметрлер, Қала, Бұлт), әрқайсысы өз ішкі бетінде, жоғарыда файлдан қосу/көшірме жүктеу; «+» 2-қадамында санаттар түсті белгілі торда, 3-қадам «Төледім ₸…» түрінде.
- **Ортадағы «+» (санперне):** қолданба ашылғанда өздігінен ашылады (Баптаулардан өшіріледі). 1) сома → 2) санат не циклді тауар (жиі қолданылғандары алдымен, «Жаңа тауар» бар) → 3) міндетті емес мәліметтер (шот, дүкен, ескертпе, күні; цикл тауарына саны мен жеңілдік). Жоғарыда Транзакция / Тауар (цикл) таңдауы: транзакцияда Шығыс/Кіріс/Аударым және санаттар, тауарда тек циклді тауарлар; камера — чек. **Чек:** Edge Function `receipt` кескінді тегін vision-модельмен оқиды → позицияларға бөледі → паста сияқты цикл тауарлары өздігінен циклге, қалғаны санат бойынша транзакцияға түседі; сен тексеріп «Растау» басасың (автоматты сақтау жоқ; позиция оқылмаса — бір жалпы сома). **Цикл + Item:** сатып алу = item (баға, саны, дүкен, жеңілдік, қала, чек); цикл-күн = сатып алулар арасындағы күндердің орташасы, ₸/күн = баға/цикл-күн; архив және ескерту қосу/өшіру; ескі циклдер бір бастапқы item болып өздігінен көшеді. Қала — Баптауларда қолмен өзгертіледі (геолокация жоқ). Ескерту — қолданба ішінде ғана (push жоқ). Чек суреті OpenRouter-ге кетеді, шот нөмірі не карта соңғы сандары көрінбесін. **Әмиян:** шоттар (қолма-қол, карта…), әр транзакция/жарна шотқа байланады, шоттар арасындағы аударым; шотсыз (ескі, ассистент жазған) жазбалар «Шотсыз» қалтада. Баптаулар — жоғарғы оң бұрыштағы белгіше.
- **Журнал (Gem Wallet үлгісінде):** ай атауы + күнтізбеден ай таңдау; күн сайын түсті плиткалар (санат түсі, белгіше, сома), плиткаға басса — өзгерту/өшіру; әр күнде «+» плиткасы сол күнге жазба қосады.
- **Санаттар (Профиль → Санаттар):** тізім → санаттың ішіне кіру (Өзгерту · Тарих · Summary, ішкі санаттар, «N жазбада қолданылған») → «Жаңа» форма: атау, орны, бюджет, 11 түс + өз түсің, 36 белгіше. Санат атауы жасалған соң өзгермейді. Бюджет Summary-де көрсетіледі, шектелмейді.
- **Цикл-күн міндетті емес:** бос қалдырса, 2 сатып алудан кейін өздігінен есептеледі.
- **Баптаулар:** бастапқы капитал, кіріс, тұрақты шығын; бұлт күйі; JSON көшірме (файлдан қосу — бар жазбаларға қосылады).
- **Мақсатқа жарна** — аударым: қолжетімді қалдықтан шығады, мақсатқа түседі. Мақсатты өшірсең, жарналар қалдыққа қайтады.
- **Санаттар** регистрге қарамай біріктіріледі («тамақ» = «Тамақ»).
- **Бұлт.** Hub-қа кірген болсаң (сессия ортақ), деректер Supabase `items` кестесіне синхрондалады: транзакциялар `app = 'money'` (ассистенттің «түскі асқа 2500» жазбаларымен бір кесте), қалғаны `fs_cycle`, `fs_goal`, `fs_stock`, `fs_match`, `fs_contrib`, `fs_settings`. Кірмесең не желі жоқ болса, қосымша құрылғыда жұмыс істей береді, өзгерістер кезекке түсіп, кейін жіберіледі. Алғашқы синхронда жергілікті деректер серверге қосылады (бар жазбалар өшпейді).
- Код: `finsaulyq/core.js` — есептеу және жол түрлендіру (`test/finsaulyq.test.mjs`), `sync.js` — бұлт, `app.js` — интерфейс.

## Жаңа қосымша қосу

Екі жерге бір-бір жазба:

1. `supabase/functions/assistant/core.ts` → `APPS` — өрістері және ассистент шақыратын құралдың аты.
2. `index.html` → `APPS` — экрандағы аты, түсі, тізімде не көрсетілетіні (түсін `:root` ішіне `--c-<id>` деп қос).

Сосын функцияны қайта жариялау керек (Claude-ға «функцияны жаңарт» десең жеткілікті).

## Тексеру

```
node --test test/core.test.ts
```

Ассистенттің негізгі логикасы (құралдарды орындау, модельден модельге ауысу, деректерді тексеру) осы тесттермен тексеріледі.
